This mode allows for an arbitrary primordial spectrum {\ttfamily P(k)} to be calculated by an external command and passed to CLASS. That external command may be anything that can be run in the shell\+: a python script, some compiled C or Fortran code... This command is executed from within CLASS, and CLASS is able to pass it a number of parameters defining the spectrum (an amplitude, a tilt...). Those parameters can be used in a Markov chain search performed by Monte\+Python.

This mode includes the simple case of a precomputed primordial spectrum stored in a text file. In that case, the {\ttfamily cat} shell command will do the trick (see below).

Currently, scalar and tensor spectra of perturbations of adiabatic modes are supported.\hypertarget{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md25}{}\doxysection{Use case \#1\+: reading the spectrum from a table}\label{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md25}
In this case, say the file with the table is called {\ttfamily spectrum.\+txt}, located under {\ttfamily /path/to}, simply include in the {\ttfamily .ini} file \begin{DoxyVerb}command = cat path/to/spectrum.txt
\end{DoxyVerb}
 It is necessary that 1st 4 characters are exactly {\ttfamily cat}.\hypertarget{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md26}{}\doxysection{Use case \#2\+: getting the spectrum from an external command}\label{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md26}
Here an external command is called to generate the spectrum; it may be some compiled C or Fortran code, a python script... This command may be passed up to 10 floating point arguments, named {\ttfamily custom1} to {\ttfamily custom10}, which are assigned values inside the {\ttfamily .ini} file of CLASS. The {\ttfamily command} parameter would look like \begin{DoxyVerb}command = /path/to/example.py
\end{DoxyVerb}
 if it starts with {\ttfamily \#/usr/bin/python}, otherwise \begin{DoxyVerb}command = python /path/to/example.py
\end{DoxyVerb}
 As an example of the 1st use case, one may use the included script {\ttfamily generate\+\_\+\+Pk\+\_\+example.\+py}, which implements a single-\/field slow-\/roll spectrum without running, and takes 3 arguments\+:
\begin{DoxyItemize}
\item {\ttfamily custom1} -- the pivot scale ({\ttfamily k\+\_\+0 = 0.\+05 1/\+Mpc} for Planck).
\item {\ttfamily custom2} -- the amplitude of the scalar power spectrum.
\item {\ttfamily custom3} -- the scalar spectral index.
\end{DoxyItemize}

In order to use it, the following lines must be present in the parameter file\+: \begin{DoxyVerb}P_k_ini type = external_Pk
command = /path/to/CLASS/external_Pk/generate_Pk_example.py
custom1 = 0.05
custom2 = 2.2e-9
custom3 = 1.
\end{DoxyVerb}
 Defined or not (in that case, 0-\/valued), parameters from {\ttfamily custom4} to {\ttfamily custom10} will be passed to the example script, which should ignore them. In this case, CLASS will run in the shell the command \begin{DoxyVerb}/path/to/CLASS/external_Pk/generate_Pk_example.py 0.05 2.2e-9 1. 0 0 0 0 0 0 0
\end{DoxyVerb}
 If CLASS fails to run the command, try to do it directly yourself by hand, using exactly the same string that was given in {\ttfamily command}.\hypertarget{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md27}{}\doxysection{Output of the command / format of the table}\label{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md27}
The command must generate an output separated into lines, each containing a tuple ({\ttfamily k}, {\ttfamily P(k)}). The following requirements must be fulfilled\+:


\begin{DoxyItemize}
\item Each line must contain 2 (3, if tensors) floating point numbers\+: {\ttfamily k} (in {\ttfamily 1/\+Mpc} units) and {\ttfamily P\+\_\+s(k)} (and {\ttfamily P\+\_\+t(k)}, if tensors), separated by any number of spaces or tabs. The numbers can be in scientific notation, e.\+g. {\ttfamily 1.\+4e-\/3}.
\item The lines must be sorted in increasing values of {\ttfamily k}.
\item There must be at least two points {\ttfamily (k, P(k))} before and after the interval of {\ttfamily k} requested by CLASS, in order not to introduce unnecessary interpolation error. Otherwise, an error will be raised. In most of the cases, generating the spectrum between {\ttfamily 1e-\/6} and {\ttfamily 1 1/\+Mpc} should be more than enough.
\end{DoxyItemize}\hypertarget{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md28}{}\doxysection{Precision}\label{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md28}
This implementation properly handles double-\/precision floating point numbers (i.\+e. about 17 significant figures), both for the input parameters of the command and for the output of the command (or the table).

The sampling of {\ttfamily k} given by the command (or table) is preserved to be used internally by CLASS. It must be fine enough a sampling to clearly show the features of the spectrum. The best way to test this is to plot the output/table and check it with the naked eye.

Another thing to have in mind arises at the time of convolving with the transfer functions. Two precision parameters are implied\+: the sampling of {\ttfamily k} in the integral, given by {\ttfamily k\+\_\+step\+\_\+trans}, and the sampling of the transfer functions in {\ttfamily l}, given by {\ttfamily l\+\_\+logstep} and {\ttfamily l\+\_\+linstep}. In general, it will be enough to reduce the values of the first and the third parameters. A good start is to give them rather small values, say {\ttfamily k\+\_\+step\+\_\+trans=0.\+01} and {\ttfamily l\+\_\+linstep=1}, and to increase them slowly until the point at which the effect of increasing them gets noticeable.\hypertarget{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md29}{}\doxysection{Parameter fit with Monte\+Python}\label{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md29}
(Monte\+Python)\mbox{[}\href{http://montepython.net/}{\texttt{ http\+://montepython.\+net/}}\mbox{]} is able to interact with the {\ttfamily external\+\_\+\+Pk} mode transparently, using the {\ttfamily custom} parameters in an MCMC fit. One must just add the appropriate lines to the input file of Monte\+Python. For our example, if we wanted to fit the amplitude and spectral index of the primordial spectrum, it would be\+: \begin{DoxyVerb}data.cosmo_arguments['P_k_ini type'] = 'external_Pk'
data.cosmo_arguments['command'] = '/path/to/CLASS/external_Pk/generate_Pk_example.py'
data.cosmo_arguments['custom1'] = 0.05                                   # k_pivot
data.parameters['custom2']      = [ 2.2,  0, -1,  0.055, 1.e-9, 'cosmo'] # A_s
data.parameters['custom3']      = [  1.,  0, -1, 0.0074,     1, 'cosmo'] # n_s
\end{DoxyVerb}
 Notice that since in our case {\ttfamily custom1} represents the pivot scale, it is passed as a (non-\/varying) argument, instead of as a (varying) parameter.

In this case, one would not include the corresponding lines for the primordial parameters of CLASS\+: {\ttfamily k\+\_\+pivot}, {\ttfamily A\+\_\+s}, {\ttfamily n\+\_\+s}, {\ttfamily alpha\+\_\+s}, etc. They would simply be ignored.\hypertarget{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md30}{}\doxysection{Limitations}\label{md__Users_hiromac7_Downloads_komatsuBiref_birefclass_v1_external_Pk_README_autotoc_md30}

\begin{DoxyItemize}
\item So far, this mode cannot handle vector perturbations, nor isocurvature initial conditions.
\item The external script knows nothing about the rest of the CLASS parameters, so if it needs, e.\+g., {\ttfamily k\+\_\+pivot}, it should be either hard coded, or its value passed as one of the {\ttfamily custom} parameters. 
\end{DoxyItemize}
