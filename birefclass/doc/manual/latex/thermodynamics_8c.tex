\doxysubsection{Detailed Description}
Documented thermodynamics module

Julien Lesgourgues, 6.\+09.\+2010

Deals with the thermodynamical evolution. This module has two purposes\+:


\begin{DoxyItemize}
\item at the beginning, to initialize the thermodynamics, i.\+e. to integrate the thermodynamical equations, and store all thermodynamical quantities as a function of redshift inside an interpolation table. The current version of recombination is based on RECFAST v1.\+5. The current version of reionization is based on exactly the same reionization function as in CAMB, in order to make allow for comparison. It should be easy to generalize the module to more complicated reionization histories.
\item to provide a routine which allow other modules to evaluate any thermodynamical quantities at a given redshift value (by interpolating within the interpolation table).
\end{DoxyItemize}

The logic is the following\+:


\begin{DoxyItemize}
\item in a first step, the code assumes that there is no reionization, and computes the ionization fraction, Thomson scattering rate, baryon temperature, etc., using RECFAST. The result is stored in a temporary table \textquotesingle{}recombination\+\_\+table\textquotesingle{} (within a temporary structure of type \textquotesingle{}recombination\textquotesingle{}) for each redshift in a range 0 $<$ z $<$ z\+\_\+initial. The sampling in z space is done with a simple linear step size.
\item in a second step, the code adds the reionization history, starting from a redshift z\+\_\+reio\+\_\+start. The ionization fraction at this redshift is read in the previous recombination table in order to ensure a perfect matching. The code computes the ionization fraction, Thomson scattering rate, baryon temperature, etc., using a given parametrization of the reionization history. The result is stored in a temporary table \textquotesingle{}reionization\+\_\+table\textquotesingle{} (within a temporary structure of type \textquotesingle{}reionization\textquotesingle{}) for each redshift in the range 0 $<$ z $<$ z\+\_\+reio\+\_\+start. The sampling in z space is found automatically, given the precision parameter \textquotesingle{}reionization\+\_\+sampling\textquotesingle{}.
\item in a third step, the code merges the two tables \textquotesingle{}recombination\+\_\+table\textquotesingle{} and \textquotesingle{}reionization\+\_\+table\textquotesingle{} inside the table \textquotesingle{}thermodynamics\+\_\+table\textquotesingle{}, and the temporary structures \textquotesingle{}recombination\textquotesingle{} and \textquotesingle{}reionization\textquotesingle{} are freed. In \textquotesingle{}thermodynamics\+\_\+table\textquotesingle{}, the sampling in z space is the one defined in the recombination algorithm for z\+\_\+reio\+\_\+start $<$ z $<$ z\+\_\+initial, and the one defined in the reionization algorithm for 0 $<$ z $<$ z\+\_\+reio\+\_\+start.
\item at this stage, only a few columns in the table \textquotesingle{}thermodynamics\+\_\+table\textquotesingle{} have been filled. In a fourth step, the remaining columns are filled, using some numerical integration/derivation routines from the \textquotesingle{}array.\+c\textquotesingle{} tools module.
\item small detail\+: one of the columns contains the maximum variation rate of a few relevant thermodynamical quantities. This rate will be used for defining automatically the sampling step size in the perturbation module. Hence, the exact value of this rate is unimportant, but its order of magnitude at a given z defines the sampling precision of the perturbation module. Hence, it is harmless to use a smoothing routine in order to make this rate look nicer, although this will not affect the final result significantly. The last step in the thermodynamics\+\_\+init module is to perform this smoothing.
\end{DoxyItemize}

In summary, the following functions can be called from other modules\+:


\begin{DoxyEnumerate}
\item \mbox{\hyperlink{thermodynamics_8c_a1acbfae38edb0c73d8991645f89b2d13}{thermodynamics\+\_\+init()}} at the beginning (but after \mbox{\hyperlink{background_8c_afeb0656453b92be39c60fb3fb1abd910}{background\+\_\+init()}})
\item \mbox{\hyperlink{thermodynamics_8c_a5763e8991ba30efe92c3007d1abfee95}{thermodynamics\+\_\+at\+\_\+z()}} at any later time
\item \mbox{\hyperlink{thermodynamics_8c_a689045596045ab02bb1853298d81f634}{thermodynamics\+\_\+free()}} at the end, when no more calls to \mbox{\hyperlink{thermodynamics_8c_a5763e8991ba30efe92c3007d1abfee95}{thermodynamics\+\_\+at\+\_\+z()}} are needed 
\end{DoxyEnumerate}

Subroutine evaluating the derivative with respect to redshift of thermodynamical quantities (from RECFAST version 1.\+4).

Computes derivatives of the three variables to integrate\+: $ d x_H / dz, d x_{He} / dz, d T_{mat} / dz $.

This is one of the few functions in the code which are passed to the generic\+\_\+integrator() routine. Since generic\+\_\+integrator() should work with functions passed from various modules, the format of the arguments is a bit special\+:


\begin{DoxyItemize}
\item fixed parameters and workspaces are passed through a generic pointer. Here, this pointer contains the precision, background and recombination structures, plus a background vector, but generic\+\_\+integrator() doesn\textquotesingle{}t know its fine structure.
\item the error management is a bit special\+: errors are not written as usual to pth-\/$>$error\+\_\+message, but to a generic error\+\_\+message passed in the list of arguments.
\end{DoxyItemize}
